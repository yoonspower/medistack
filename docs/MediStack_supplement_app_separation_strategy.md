# MediStack — 영양제 앱 분리 전략 (DRAFT)

> 작성일: 2026-06-14. **전략 문서 초안 전용 — 코드/UI/데이터/스키마 변경 0.** 본 문서는 방향성·경계 합의용이며, 실제 기능 구현은 별도 승인·라운드에서만.
>
> 전제: MediStack 은 **식약처 허가사항 기반 약-영양소 참고정보 베타**(진단·처방·복약지시·영양제 추천 아님). 이 정체성은 분리 전략에서도 불변. 관련 문서: `MediStack_monetization_strategy_v1_1.md` §4(제품/제휴 분리), `MediStack_disclaimer_and_terms_draft.md` §5(상거래 부재).

## 0. 한 줄 방향

**MediStack(약-영양소 참고정보)과 영양제 앱(영양제 이해·스택 관리·성분 비교)은 별개의 앱으로 분리한다. 같은 앱 안에서 "약 검색 → 영양제 추천 → 구매 링크"로 이어지는 동선은 금지한다. 두 앱은 데이터·UX·브랜드 동선을 공유하지 않는다.**

---

## 1. 절대 원칙 (분리에서도 불변)

- ❌ **같은 앱 안 "약 검색 → 영양제 추천 → 구매 링크" 흐름 금지.** MediStack 안에서도, 영양제 앱 안에서도 금지.
- ❌ **영양제 앱이 MediStack 의 약-영양소 relation 데이터에 직접 연결 금지.** (상세는 §5 경계 계약)
- ❌ 영양제 앱은 **제품 추천·구매 동선이 기본값이 아니다.** 제품 링크는 나중에 별도 검토 대상(지금 아님).
- ❌ 복용 지시·진단·처방·치료·위험 확정·"드세요/보충하세요" 표현 금지(양쪽 앱 공통).
- ❌ "식약처 승인 / 법적 문제없음 확정 / 약사 검수 완료" 표현 금지.
- ✅ MediStack 은 **"한국용 약-영양소 참고정보 베타"로 순수 유지.** published/clinical_reviewed false 유지.
- ✅ 영양제 앱은 **"정보 이해 / 정리 / 비교"** 가치이지, "무엇을 사라/먹어라"를 대신하는 가치가 아니다.

---

## 2. 왜 한 앱 안에서 약 검색 → 영양제 추천 → 구매를 금지하는가

세 가지 이유. 각각 독립적으로도 금지 사유가 된다.

### 2.1 의료 참고정보의 중립성 (medical-reference neutrality)
- MediStack 의 가치는 **"팔 게 없으니 과장할 이유가 없다"**는 중립성에서 나온다.
- 같은 화면에서 약을 검색하고 그 결과로 영양제를 추천·판매하면, 참고정보가 **판매를 정당화하는 도구**로 읽힌다.
- "이 약을 먹으면 이 영양소가 부족할 수 있다 → 그러니 이 제품을 사라"는 동선은 **참고정보를 구매 권유의 미끼로 전락**시킨다. 정보의 중립성이 곧 제품성인 앱에서 이는 자기파괴적.

### 2.2 규제 리스크 (regulatory risk)
- 약 검색 결과 → 특정 영양제 추천/판매는 **"의약품 정보 기반 건강기능식품 권유"** 동선으로, 의료·광고·건강기능식품 표시·전자상거래 등 여러 규제 표면에 동시에 노출된다.
- 베타 참고정보 앱이 감당할 수 있는 표면이 아니다. 추천·판매를 섞는 순간 심사·법적 리스크가 **단계적으로 증가**한다.
- 분리하면 각 앱의 규제 성격이 명확해진다: MediStack = 참고정보(상거래 0), 영양제 앱 = 정보/비교(추천·판매 0, 추후 제품링크는 별도 검토).

### 2.3 신뢰 (trust)
- 사용자가 "이 앱은 영양제 팔려고 약 위험을 과장한다"고 한 번 의심하면, **참고정보 전체의 신뢰가 무너진다.**
- 신뢰는 MediStack 의 유일한 자산이다. 구매 동선 한 줄로 교환할 수 있는 것이 아니다.

> 요약: 중립성·규제·신뢰 어느 축으로 봐도, **약 검색과 영양제 구매를 같은 동선에 두면 안 된다.** 그래서 앱 자체를 분리한다.

---

## 3. MediStack 본체 (변하지 않음)

- 성격: **한국용 약-영양소 참고정보 베타** (식약처 허가사항 기반).
- 영양제 추천·구매·제휴 **없음**(무료/유료 어느 쪽도). 유료화 방향은 §`MediStack_monetization_strategy_v1_1.md` 의 "내 약 관리 도구"(저장·정리·상담 준비)로 한정.
- 영양제 앱으로 **넘기는 버튼·링크·핸드오프 없음.** MediStack 화면 안에서 영양제 앱을 띄우거나, 약 결과를 영양제 앱으로 전달하지 않는다.

---

## 4. 별도 영양제 앱 — 방향과 후보 기능

방향: **"영양제 이해 / 내 스택 관리 / 성분 비교"** — 정보·관리·비교 도구이지, 제품 추천 엔진이 아니다.

후보 기능은 전부 **정보/비교 성격**이며, **제품 추천이 아니다.** 약-영양소 relation 과 직접 연결하지 않는다.

| 기능 | 설명 | 성격(중립성 정렬) |
|---|---|---|
| 영양제 성분 검색 | 성분명으로 일반 정보(역할·일반적 섭취 맥락) 확인 | 정보 — 추천 아님 |
| 항산화 네트워크 설명 | 비타민C·E·글루타치온 등 항산화 성분이 서로 어떻게 작용하는지 **개념 설명** | 정보 — 특정 제품/용량 권유 아님 |
| 비타민C 메가도스 중립 설명 | 메가도스를 **권장하지 않고**, 어떤 주장이 있고 한계가 무엇인지 **중립 설명** | 정보 — "많이 드세요" 금지 |
| 내 스택 등록 | 현재 먹는 영양제를 목록으로 등록·보관 | 관리(보관) — 복용 지시 아님 |
| 중복 성분 체크 | 등록한 제품들 사이 **같은 성분이 겹치는지** 표시 | 비교/점검 — "줄이세요/늘리세요" 단정 금지, 사실 표시만 |
| 과다 가능성 체크 | 합산 시 **일반 상한 참고치 대비 높을 가능성**을 중립 표시 | 점검 — 위험 확정 금지, 상담 권고 |
| 성분 형태 비교 | 같은 성분의 형태(예: 마그네슘 산화물 vs 구연산염) **차이 설명** | 비교 — 우월 제품 단정 아님 |
| 성분당 가격 비교 | 단위 성분량당 가격을 **계산해 비교**(특정 제품 판매 아님) | 비교 — 정보 계산, 구매 링크 아님 |
| 복용 타이밍 플래너 | 사용자가 등록한 성분의 **일반적 섭취 타이밍 정리**(개인 일정 보조) | 관리 — 처방 아님, 일반 정보 정리 |

> 공통: 모든 기능은 **"제품을 추천"하지 않고 "성분 정보/비교"를 제공**한다. "이 제품을 사라"가 아니라 "이 성분은 이렇고, 네 스택은 이렇게 겹친다"까지만.

### 4.1 영양제 앱에서도 금지

- ❌ 제품 추천 랭킹·"베스트 영양제"·구매 버튼·제휴 링크(지금 단계). 제품 링크는 §6 별도 검토.
- ❌ "이걸 드세요 / 이게 부족하니 보충하세요" 단정. (중립 설명·상담 권고로)
- ❌ MediStack 의 약-영양소 relation 을 끌어와 "이 약 먹으니 이 영양제 사라"로 잇는 것.
- ❌ 진단·치료 주장(예: "불면증에 이 성분").

## 5. 경계 계약 (Boundary Contract) — 두 앱 사이를 절대 넘지 않는 것

이 절은 **하드 룰**이다. 분리의 핵심이며, 어떤 구현·기획도 여기를 넘으면 정책 위반이다.

### 5.1 데이터 경계 — NEVER cross

- 🚫 **MediStack 의 약-영양소 relation 데이터(`relations` / relation_card)를 영양제 앱이 읽거나 가져오지 않는다.** 공유 DB·공유 API·공유 export 파일·복사본 모두 금지.
- 🚫 영양제 앱은 **약(의약품) 검색 결과를 입력으로 받지 않는다.** "이 약을 먹는다"는 정보가 영양제 앱의 추천/비교 입력으로 흘러가면 안 된다.
- 🚫 두 앱이 **같은 사용자 식별자로 데이터를 합쳐** "약+영양제 통합 판단"을 만들지 않는다.
- ✅ 영양제 앱은 **자체 성분 정보 데이터셋**을 따로 둔다(약-영양소 relation 과 출처·스키마·운영을 분리).

### 5.2 UX / 동선 경계 — NEVER cross

- 🚫 **MediStack 약 상세 → 영양제 앱(또는 영양제 추천)으로 가는 버튼·딥링크·핸드오프 없음.**
- 🚫 **영양제 앱 → MediStack 약 결과로 가는 "이 약이면 이 영양제" 역동선 없음.**
- 🚫 한 앱의 결과 화면에 다른 앱의 추천/제품을 끼워 넣지 않는다.
- 🚫 "약을 검색했으니 영양제를 보여준다"는 **결과 기반 크로스셀 금지**(양방향).

### 5.3 브랜드 / 상거래 경계

- 🚫 MediStack 화면 안 제품·구매·제휴 UI 없음(기존 불변 원칙 유지).
- 🚫 영양제 앱의 구매/제휴(있게 된다면)가 MediStack 신뢰를 빌려 쓰지 않는다("MediStack 추천 영양제" 류 금지).
- ✅ 두 앱은 **이름·브랜드·데이터 출처를 명확히 구분**한다.

### 5.4 금지되는 크로스오버 — 구체 예시 (이런 모양이면 전부 위반)

아래는 "분리가 깨지는" 구체 형태다. 설계·기획·구현 어느 단계든 이런 모양이 보이면 §5 위반으로 즉시 차단·되돌린다. (추상 원칙을 못 알아보고 통과시키는 일을 막기 위한 체크리스트다.)

| # | 금지되는 구체 형태 | 어느 경계 위반 | 올바른 대안 |
|---|---|---|---|
| 1 | MediStack 약 상세 화면 하단에 "이 약과 관련된 영양제 보기 →"(영양제 앱 딥링크) 버튼 | UX/동선 §5.2 | 버튼 없음. 사용자가 스스로 별도 앱에서 검색(§5.4) |
| 2 | MediStack 검색 결과를 영양제 앱이 URL 파라미터/공유 인텐트로 받아 "이 약 복용 중이면 추천 성분" 표시 | 데이터 §5.1 + 동선 §5.2 | 영양제 앱은 약 입력을 받지 않음. 성분 검색만 |
| 3 | 두 앱이 같은 백엔드/같은 export JSON(`relations`·relation_card)을 읽음 | 데이터 §5.1 | 영양제 앱은 자체 성분 데이터셋(§5.1 ✅) |
| 4 | 영양제 앱 안에 "MediStack 가 추천하는 영양제" / "약사 검수 영양제" 라벨 | 브랜드 §5.3 + 표현 금지 | MediStack 신뢰를 빌리지 않음. 라벨 자체 금지 |
| 5 | 한 계정/한 기기 식별자로 약 목록 + 영양제 스택을 합쳐 "통합 위험 점수" 생성 | 데이터 §5.1 | 통합 판단 생성 금지. 각 앱은 자기 데이터만 |
| 6 | MediStack 푸시/배너로 "영양제 앱에서 부족 성분 확인하세요" 유도 | 동선 §5.2 + 행동 유도 | 크로스 프로모션 형태의 동선 금지 |
| 7 | 영양제 앱 "내 스택" 화면에 "이 성분은 ○○ 약과 상호작용" 표시(MediStack relation 재현) | 데이터 §5.1 | relation 재현·복제 금지. 성분 정보까지만 |
| 8 | 단일 코드베이스·단일 스토어 리스팅에 두 기능을 한 앱으로 묶음 | 분리 자체 위반(§0) | 별개 앱·별개 리스팅·별개 코드 |

> 위 8가지는 "편의" 또는 "사용자 도움"처럼 포장돼 들어오기 쉽다. 그러나 전부 **참고정보를 구매/추천 동선의 입구로 전용**하거나 **두 앱을 데이터/동선으로 결합**한다. 어떤 명분이든 §1·§5 가 우선한다.

### 5.5 넘어가도 되는 것 (참고)

- ✅ **사람의 판단**: 사용자가 MediStack 에서 본 참고정보를 머릿속에 두고, 별도로 영양제 앱에서 성분을 찾아보는 것 — 이는 **앱 간 동선이 아니라 사용자 행동**이며 막을 수 없고 막지 않는다.
- ✅ **각 앱 자체의 면책·상담 권고 톤**은 공유해도 된다(두 앱 다 "스스로 판단 금지, 상담 권고").
- ✅ **공통 디자인 시스템·컴포넌트 라이브러리 재사용**(색·폰트·버튼 등 순수 UI 자산)은 가능 — 단, 이는 §5.3 의 "브랜드 동선 공유"(상호 추천·신뢰 차용)와 다르며, 데이터·추천·핸드오프를 동반하지 않을 때만.

> 경계 계약 한 줄: **relation 데이터, 약-결과 입력, 앱 간 추천 핸드오프 — 이 셋은 두 앱 사이를 절대 넘지 않는다.**

### 5.6 분리 자가 점검(self-test) — 설계/기획 채택 전 1문항

> **"이 기능이 두 앱을 데이터·동선·브랜드 중 하나라도 묶거나, 약 정보를 영양제 추천·구매의 입구로 만드는가?" → 예이면 채택하지 않는다(§5 위반).**

이 한 문항을 통과하지 못하는 모든 제안은, 그 반대(명시적 금지)로 처리한다. **분리를 깨는 방향의 "개선"은 개선이 아니다.**

---

## 6. 제품 링크는 나중에 별도 검토

- 제품 추천·구매·제휴는 **지금 도입하지 않는다.** 영양제 앱조차 1차 방향은 "정보/비교"이며 구매 동선이 없다.
- 제품 링크를 검토하더라도: ① MediStack 본체에는 영구히 넣지 않는다, ② 영양제 앱 안에서만, ③ **별도 승인 라운드 + 별도 법적/심사 검토**를 거친 뒤에만 검토 대상이 된다.
- 어떤 경우에도 **"약 검색 → 영양제 구매"** 동선은 부활하지 않는다(§2).

## 7. 단계 제언 (구현 아님)

1. **지금**: MediStack 은 약-영양소 참고정보 베타로 유지·확장(현행 트랙). 영양제 앱은 아직 별도 앱 아이디어 단계.
2. **다음(영양제 앱 검토 시)**: "성분 검색 + 내 스택 등록 + 중복/과다 체크"를 정보/비교 MVP 로 우선 검토 — 가장 안전·차별적. relation 비연결·추천 비포함 전제.
3. **분리 유지**: 두 앱 코드/데이터/동선을 처음부터 분리해 설계. 경계 계약(§5)을 설계 시점부터 박는다.
4. **제품 링크**: 별도 트랙·별도 승인(§6).
