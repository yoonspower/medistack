# MediStack — 유료화 / 제품 방향 전략 초안 v1.1

> 작성일: 2026-06-13. **전략 문서 초안 전용 — 코드/UI/결제 구현 0.** 본 문서는 방향성 합의용이며, 실제 기능 구현은 별도 승인·라운드에서만.
>
> 전제: MediStack 은 **식약처 허가사항 기반 약-영양소 참고정보 베타**(진단·처방·복약지시·영양제 추천 아님). 이 정체성은 유료화에서도 불변.

---

## 0. 한 줄 방향

**MediStack 본체는 "약-영양소 참고정보 도우미"로 유지하고, 유료화는 "내 약 관리 도구"(저장·정리·상담 준비)로 간다. 영양제 추천·구매·제휴는 본체에 넣지 않고, 필요하면 별도 앱으로 분리한다.**

---

## 1. 절대 원칙 (유료화에서도 불변)

- ❌ **본체에 영양제 추천·구매링크·제휴 없음.** 무료/유료 어느 쪽에서도 제품 판매 동선 금지.
- ❌ 복용 지시·진단·처방·치료·위험 확정·"드세요/보충하세요" 표현 금지.
- ❌ "식약처 승인 / 법적 문제없음 확정 / 약사 검수 완료" 표현 금지.
- ✅ 베타 운영 전제(문제 시 사후 대응 가능). published/clinical_reviewed false 유지.
- ✅ 유료 기능은 **"정보를 더 잘 정리·보관·상담 준비"** 가치이지, "더 위험한 의학 판단을 대신"하는 가치가 아니다.

> 즉 유료화의 가치 축 = **개인화 + 정리/보관 + 상담 준비**. 의학적 단정 강화가 아니다.

---

## 2. 유료화 방향 — "내 약-영양소 관리 도구"

수익 모델은 **광고·제휴가 아니라 Plus 유료 기능**(초기엔 저가 평생 구매, §3.1) 기반의 개인 관리 도구로 제안한다. 후보 기능(전부 "정보 정리/상담 준비" 성격):

| 기능 | 설명 | 안전성 |
|---|---|---|
| 내 약 목록 저장 | 복용 중인 약을 검색해 내 목록에 저장 | 정보 보관일 뿐, 복용 지시 아님 |
| 가족 프로필 | 가족 구성원별 약 목록 분리 관리 | 〃 |
| 약-영양소 참고정보 모아보기 | 내 약들에 연결된 참고정보(relation 카드)를 한 화면에 | 기존 참고정보 재집계, 신규 의학판단 0 |
| 약사/의사 질문 생성 | "약사·의사에게 물어볼 질문" 체크리스트 자동 구성(예: 장기복용 시 영양소 상태 확인 문의) | **상담 유도**(스스로 판단 X) — 안전 정렬 |
| 검색 히스토리 | 최근 검색·자주 찾는 약 | 편의 |
| 리포트 저장 / PDF 내보내기 | 내 약 목록+참고정보를 PDF/이미지로 저장 | 보관·공유용 |
| 복용 메모 | 내 약별 자유 메모(예: "아침 식후 복용 중") 보관 | 사용자 자가 기록 보관일 뿐, 앱이 지시·해석 X |
| 변경 이력 | 내 약 목록·메모의 추가/삭제/수정 이력 보기 | 사용자 기록의 타임라인, 신규 판단 0 |
| 관심 영양소 북마크 | 자주 보는 영양소(예: 마그네슘) 즐겨찾기 | 편의·탐색 |
| relation_card 업데이트 알림 | 내 약/북마크에 연결된 참고정보 카드가 갱신되면 알림 | **정보 갱신 고지**일 뿐, 새 권고·복용지시 아님 |

> 핵심: 위 기능은 전부 **"내 데이터를 모아 약사·의사 상담을 준비"** 하게 돕는다. MediStack 의 면책·참고정보 톤과 충돌하지 않는다.
>
> ⚠️ **알림 기능 주의**: `relation_card 업데이트 알림`은 "정보가 갱신되었다"는 **사실 고지**까지만이다. "○○를 보충하세요/중단하세요" 같은 행동 유도 푸시는 금지(복용지시·의학 단정에 해당). 알림은 카드를 다시 열어 보도록 유도하는 수준으로 한정한다.

| 구분 | Free | Plus(유료) |
|---|---|---|
| 약 검색 | ✅ 전체 | ✅ 전체 |
| name_only 품목명 확인 | ✅ | ✅ |
| 기본 relation_card 보기 | ✅ | ✅ |
| 면책·출처·복합제 배너 | ✅ | ✅ |
| 내 약 목록 저장 | △ 제한적(예: 5개) | ✅ 무제한 |
| 가족 프로필 | ❌ | ✅ |
| 참고정보 모아보기 | ❌ | ✅ |
| 약사/의사 질문 생성 | ❌ | ✅ |
| 검색 히스토리 | △ 최근 몇 건 | ✅ 전체 |
| 리포트 저장 / PDF 내보내기 | ❌ | ✅ |
| 복용 메모 | ❌ | ✅ |
| 변경 이력 | ❌ | ✅ |
| 관심 영양소 북마크 | △ 소수 | ✅ 무제한 |
| relation_card 업데이트 알림 | ❌ | ✅ |

> **Free 의 핵심 약속**: 약 검색·`name_only` 품목명 확인·기본 `relation_card` 보기·면책/출처 표시·제한적 "내 목록 저장"까지는 **항상 무료**다. 즉 "내 약이 어떤 영양소 참고정보를 갖는지 확인"이라는 본질 가치는 결제 없이 쓸 수 있고, Plus 는 그 위에 **정리·보관·상담 준비**를 얹는다. 정보 접근을 페이월 뒤에 가두지 않는다(참고정보 도우미의 신뢰 원칙).
>
> 가격·과금 방식은 §3.1 참조. **본 문서는 기능 경계 + 가격 후보까지만**(실제 결제 구현·상품 등록은 별도 승인 라운드).

### 3.1 가격 후보 (초안)

| 모델 | 후보가 | 우선순위 | 비고 |
|---|---|---|---|
| **평생 구매(1회)** | **4,900원 또는 9,900원** | **1순위(권장)** | Plus 기능 평생 해금. 초기 개인 개발자에게 가장 적합 |
| 월 구독 | 1,100~2,900원 | 후순위 | 정기 결제. 초기엔 보류 |

**왜 초기에는 "저가 평생 구매"가 월 구독보다 적합한가 (개인 개발자 + 베타 의료-참고 도구 기준):**

1. **지원·운영 부담 최소화.** 개인 개발자 1인 운영이라 정기 결제는 갱신 실패·환불·영수증 검증·구독 상태 동기화 등 **지속 CS/유지보수 부담**을 만든다. 1회 평생 구매는 결제 이후 운영 손이 거의 안 든다.
2. **베타 신뢰 구축.** 아직 `published/clinical_reviewed = false` 인 **베타 참고 도구**에 매달 돈을 내라고 하면 심리 저항이 크다. 저가 1회 구매는 "한 번 사두면 끝"이라는 안심감을 주어 **초기 신뢰·전환에 유리**하다. 의료-인접 정보 도구일수록 "계속 과금당한다"는 인상은 신뢰에 역효과.
3. **정기 결제 마찰 회피.** 니치(약-영양소 참고)·저빈도 사용 도구는 "이번 달 안 썼는데 또 빠져나갔다 → 해지·악평·환불"로 이어지기 쉽다. **반복 청구 마찰**은 작은 도구에서 손해가 크다. 1회 구매는 이 마찰 자체가 없다.
4. **가격 심리.** 4,900~9,900원은 "커피 1~2잔" 수준의 **낮은 진입 장벽 + 즉시 결정** 가격대. 월 구독은 누적 부담 계산을 유발해 결정을 미루게 한다.

> 월 구독은 **검색·알림 등 지속 가치가 충분히 입증되고 사용자 기반이 커진 뒤** 재검토(후순위). 초기엔 평생 구매 단일 상품이 단순하고 안전하다.
>
> 구체 금액(4,900 vs 9,900)·스토어 상품 구성·환불 정책·지역 가격은 **시장/심사 단계에서 확정**. 본 절은 방향 후보까지만.

## 4. 제품 판매/제휴는 별도 앱으로 분리 (권장)

만약 영양제 제품 추천·판매·제휴 수익을 추구한다면:

- MediStack 본체에 **넣지 않는다**(참고정보 신뢰성·면책 톤 훼손 + 심사·법적 리스크 상승).
- **별도 영양제/이커머스 앱**으로 분리하고, MediStack 과는 데이터·브랜드를 명확히 구분.
- MediStack 은 "한국용 약-영양소 참고정보 베타"로 순수 유지.

> 이유: 참고정보 도우미에 구매 동선이 섞이면 "영양제 팔려고 위험을 과장한다"는 신뢰·규제 리스크가 즉시 발생. 정보 신뢰성이 곧 제품 가치인 앱에서 이는 치명적.

## 5. 절대 수익화하지 않는 것 (What we will NOT monetize)

유료화를 하더라도 **다음 수익원은 영구히 채택하지 않는다.** 이는 §1 절대원칙의 수익 모델 적용판이다.

- ❌ **영양제 추천 수익 없음.** 검색·참고정보·Plus 어디에서도 "이 영양제를 사세요/드세요"로 이어지는 동선·추천을 만들지 않는다.
- ❌ **구매 퍼널 없음.** 약 검색 결과 → 영양제 구매로 잇는 링크·버튼·딥링크·쿠폰·제휴(affiliate) 코드 없음. 검색 결과는 **상거래 입구가 아니다.**
- ❌ **사용자 건강정보 판매·공유 없음.** 내 약 목록·복용 메모·북마크·검색 히스토리 등 사용자가 저장한 정보를 **제3자에게 판매·제공·광고 타겟팅에 활용하지 않는다.** (현 구조상 자체 서버·로그도 없음 — 개인정보/피드백 정책 초안 참조.)
- ❌ **광고 기반 수익(특히 영양제 광고) 없음.** 참고정보 신뢰성·면책 톤과 충돌. 수익은 Plus(개인 관리 도구) 결제로만.

> 수익 = **"내 정보를 더 잘 정리·보관·상담 준비"하는 도구 값**(Plus). **사용자의 건강 데이터나 구매 동선을 파는 것이 아니다.** 이 경계는 가격·기능과 무관하게 불변.

## 6. Plus 기능의 의학 경계 (절대 넘지 않음)

Plus 기능은 **정보를 정리하고, 전문가에게 물어볼 질문을 만든다.** 답을 주지 않는다.

- Plus 는 **정리·보관·상담 준비** 가치만 제공한다. "이 약엔 마그네슘을 보충하세요", "이건 같이 드시면 안 됩니다" 같은 **답·판단·복용지시는 절대 생성하지 않는다.**
- `약사/의사 질문 생성`은 사용자가 **전문가에게 물어볼 질문**을 만들 뿐, 그 질문의 **답을 제공하지 않는다.** (예: "장기복용 시 ○○ 영양소 상태를 확인해야 하는지 약사에게 문의" — 결론이 아니라 문의 항목.)
- `참고정보 모아보기`·`리포트`는 **기존 relation_card 의 재집계·재배치**일 뿐, 신규 의학 판단·해석·점수·위험 등급을 만들지 않는다.
- `relation_card 업데이트 알림`은 "정보가 갱신됨" 사실 고지까지만. **행동 유도(보충/중단) 푸시 금지.**
- 유료라고 해서 면책·출처 표시를 약화하거나 숨기지 않는다. Plus 화면에도 공통 면책·출처 톤 유지.

> 한 줄 테스트: **"이 Plus 기능이 사용자 대신 의학적 결정을 내리거나 그렇게 보이게 하는가?" → 예이면 그 기능은 채택하지 않는다.**

## 7. 단계 제언 (구현 아님)

1. **지금**: 베타로 무료 + 신뢰 가능한 참고정보 커버리지 확장(현행 트랙)에 집중. 유료화는 사용자·리텐션 데이터 확보 후.
2. **다음**: Plus 기능 중 **"내 약 목록 저장 + 약사/의사 질문 생성"** 을 최소기능(MVP)으로 우선 검토 — 가장 안전하고 차별적. 과금은 **저가 평생 구매(§3.1)** 단일 상품부터.
3. **분리 검토**: 제품/제휴 수익은 별도 앱 트랙으로만.

## 8. 금지 / 안전 준수 (본 문서)

- ✅ **문서 초안 뿐** — 코드/UI/결제/스키마 변경 0. 데이터·src 무변경.
- ✅ 본체 제품·구매·제휴 도입 **권장하지 않음**(분리 권장). 영양제 추천 동선 0.
- ✅ 유료 기능 전부 "정보 정리/상담 준비" 성격 — 복용지시·의학 단정 강화 아님(§6 경계).
- ✅ 영양제 추천·구매 퍼널·건강정보 판매·광고 수익 **영구 배제**(§5).
- ✅ 가격은 **방향 후보**(§3.1)까지만 — 실제 금액·상품·결제는 별도 승인·심사 단계.
- ✅ published/clinical_reviewed false 유지. "승인/검수 완료" 표현 없음.
