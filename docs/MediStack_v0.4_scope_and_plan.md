# MediStack v0.4 — 범위 및 착수 계획서

작성 기준일: 2026-06-08 / 단계: **계획만** (코드·데이터·alias·DATA_URL·deploy 전부 미변경)
직전: v0.3-beta 라이브(`c1c681e`). relation 30건(DATA_URL=v0.2) + 운영 alias 53개 + alias 검색 + CI 3종 게이트 + Node24.
상위 참고: v0.3 roadmap / alias 설계·seed·운영seed / 검색합류 / 릴리즈노트.

> 이 문서는 방향·우선순위·게이트만 정의한다. 실제 데이터/alias/코드 변경·배포는 각 트랙별 PM 판정 후 별도.

---

## 0. 전제 (못박음)
- relation 데이터 추가는 **아직 보류**(계획만). alias 확장도 **계획만 먼저**.
- 에스오메프라졸 alias **계속 보류**. 제품 추천/구매/제휴 UI **금지**. published/clinical_reviewed **봉인**.
- 원문(식약처 허가사항)에 없으면 노출 금지 / 원문보다 강하면 금지 / validator PASS 없으면 배포 금지.

## 1. v0.4 목표
검색 **체감 커버리지 + 미수록 안전성**을 한 단계 올린다. relation 의학 데이터는 가능한 한 건드리지 않고:
- alias를 **53 → 100~150**으로 확장(검증된 30건 범위 내, 품질 우선).
- **UX-B(미등록 약 안내)**로 "검색 0건 = 안전" 오인을 차단.
- 에스오메프라졸/15행 처리 방침을 **문서로 확정**(데이터 변경은 별도 게이트).
- relation 확장은 **요건 충족 시에만**, 기본은 보류 유지.

## 2. v0.3에서 이어받는 불변 원칙
- alias = **검색 보조**, 의학정보 아님. alias만으로 relation 신규생성·검색풀 확장 금지.
- 검색풀은 항상 `getRenderableRelations` → excluded_v0_1/15행 구조적 진입 불가.
- alias는 relation JSON과 **별도 파일** fetch + fail-soft(실패 시 relation-only).
- alias 표면형 **prefix(startsWith) 매칭**, canonical은 정확 일치.
- **15행/에스오메프라졸 제품 alias 금지**(validator #6/#9). 칼륨 행 안전표시·제품UI 금지·disclaimers.common fail-safe.
- DATA_URL 전환·deploy 게이트 변경은 PM 판정 후. CI는 v0.1+v0.2+v0.3 alias 3종 PASS 유지.

## 3. alias 확장 53 → 100~150 전략
대상: **현행 live 14성분(제품 13성분) 범위 내**에서만. 새 약물 alias는 relation 확장(§7)과 동반해야 함.
증분 원천(품질 우선, 순열 부풀리기 금지):
- **영문 이형 보강** — 미적용 INN 변형/철자(예: torsemide↔torasemide 이미 있음, 추가 표준 변형만), 염 형태 영문(`alendronate sodium` 등 표준만).
- **한글 표기 이형** — 표준 전사 변형(하이드로클로로티아지드/히드로…, 독시사이클린 하이클레이트 등). 오타·속어 제외.
- **약칭** — 통용 약칭(HCTZ 외 표준만).
- **교차확인 2번째 품목명**(§4) — v0.2에서 원문 교차확인한 품목의 정식명/브랜드코어.
산정(현실): 위 증분으로 성분당 +3~7 → 14성분 ≈ +50~90 → **총 100~150** 도달. 300 밴드(제네릭 전수)는 v0.5+.
**금지:** 동일 의미 용량/띄어쓰기 순열을 entry로 양산(정규화로 흡수). nutrient 제품 alias. 미검증 상품명.

## 4. 교차확인 2번째 품목 alias 기준
- v0.2 Phase 2에서 **신규클래스·안전민감 행에 대해 동일 성분 2번째 품목으로 원문 교차확인**을 했음. 그 교차확인 품목명만 제품 alias 후보.
- 조건: ①그 품목이 해당 성분의 **검증된 relation 출처와 동일 성분** ②itemSeq가 실재하고 relation의 itemSeq 집합과 매칭(또는 교차확인 itemSeq를 alias의 `item_seq`로 추적) ③제품 추천 아님(검색 진입로만).
- **주의:** v0.3 운영 alias는 성분당 대표품목 1종만 썼음. 2번째 품목 추가 시 validator의 `item_seq` 매칭 규칙(#8: 해당 성분 relation의 itemSeq 집합에 속함)과 충돌 가능 → **validator 확장 필요**(§8): "2번째 itemSeq 허용 목록"을 데이터/검증에 명시하거나, item_seq 검증을 "성분 단위 화이트리스트"로 일반화. 설계 시 결정.
- 시장 전 제네릭 나열은 여전히 금지(v0.5+).

## 5. 에스오메프라졸 / 15행 재검토 처리 방침
- **기본: 보류 유지.** v0.4에서도 에스오메프라졸 제품 alias 금지, 성분 alias 보류 디폴트.
- 재검토 트랙(문서 우선, 데이터 변경은 별도 게이트):
  - **옵션 A(권장 1순위):** 에스오메프라졸 **성분 alias만** 편입(esomeprazole→id 16 Mg, live). renderable 필터로 id 15(B12)는 미노출 보장 + QA로 확인. 단 "넥시움"(제품) alias는 계속 금지.
  - **옵션 B:** 15행 자체 재검토 — 에스오메프라졸 대표 품목 허가사항 **사용상의 주의사항**에 B12 흡수장애 직접 문구가 새로 확인되면 verified 승격 후 relation 편입(이건 §7 relation 확장 트랙). v0.2 재검토에선 미확인이라 excluded 유지였음.
- 결정 순서: 먼저 §10-PM 판정으로 옵션 택1 → 택했으면 별도 게이트(데이터/alias 변경 + validator + QA).
- 어느 옵션이든 **id 15 노출은 끝까지 금지**(원문 근거 없으면).

## 6. UX-B 미등록 약 안내 범위
- 문제: 검색 0건이 "상호작용 없음/안전"으로 오인될 수 있음(현재는 일반 no-results 문구).
- v0.4 범위(보수적):
  - **명시 안내 문구** — 0건일 때 "MediStack은 일부 약-영양소 관계만 수록한 참고 베타입니다. 결과 없음이 '안전'을 뜻하지 않습니다. 복용 관련은 의사·약사와 상담하세요." 류(정확 카피 PM 확정). 기존 no-results 문구를 이 방향으로 강화.
  - alias로도 0건인 "있을 법한 약"(예: 와파린)에서 특히 중요.
- v0.4 비범위: 외부 요청 폼/수집·로그 기반 후보 큐레이션(OPS-C)은 보류(프라이버시·정적사이트 제약). 안내 문구만.
- 안전: "안전" 단정 절대 금지. 진단·복약지시 금지. 코드 변경은 states.js no-results 카피 + (선택) 검색어 echo, 제품 UI 없음.

## 7. relation 확장 여부와 보류 기준
- **기본: 보류.** v0.4는 검색 UX/안전 중심. relation 추가는 "요건 충족 시에만".
- 추가 요건(v0.2 SOP 동일, 1건이라도 어기면 제외):
  - itemSeq + **사용상의 주의사항 번호항 직접 문구** 확보(이상반응 목록만으로 금지).
  - gstack browse로 원문 직접 추출(WebFetch 단독 금지).
  - 원문보다 강한 해석 금지. antagonism·임상판단 행 금지.
  - 신규클래스·안전민감은 2번째 품목 교차확인.
- 확장 시 버전 운용: v0.2 파일 append vs v0.4 신규 export + DATA_URL 전환(roadmap §4) → 본격 확장이면 신규 파일 권장. **PM 판정.**
- 칼륨/제품/published 규칙 불변.

## 8. QA / validator 게이트
- **alias validator 확장**(필요 시): ①meta.alias_count 일치 ②lang enum(ko/en) ③item_seq 형식 ④**교차확인 2번째 품목 itemSeq 허용**(§4) ⑤정규화 충돌 가드 ⑥커버리지 경고. 회귀: v0.1/v0.2/v0.3 동작 무영향.
- **UX-B QA**: 0건 시 강화 안내 노출, "안전" 오인 카피 부재, 직접/alias/무매치 분기 정확.
- **alias 확장 QA**: 신규 alias 표본 검색→정확 성분 연결, prefix 오매칭 없음, 넥시움/에스오메프라졸 0건(또는 옵션A 채택 시 id16만), #/r/15 미노출.
- 배포 전 게이트: 로컬 QA + validator 전종 PASS → PR CI 그린 → 머지=배포 → 라이브 검증. 단계별 PM 판정.

## 9. v0.4에서 하지 않을 것
- 제네릭 상품명 전수 alias(300 밴드) → v0.5+.
- nutrient(영양소) 제품 alias / 제품·구매·제휴 UI.
- published/clinical_reviewed 승격.
- id 15 노출(원문 근거 없는 한 영구).
- OPS-C 외부 요청 폼·검색 로그 수집.
- 원문 미검증 relation·antagonism·임상판단 행.

## 10. PM 판정 필요사항
1. **착수 우선순위** — (A)alias 확장 (B)UX-B (C)에스오메프라졸/15행 재검토 (D)relation 확장 중 순서.
2. **alias 목표치** — 100~150 확정 vs 다른 상한.
3. **교차확인 2번째 품목 alias 포함 여부** + validator item_seq 규칙 일반화 방식.
4. **에스오메프라졸 재검토 옵션** — A(성분 alias만) / B(15행 relation 재검토) / 계속 보류.
5. **UX-B 안내 카피** 확정 + 검색어 echo 포함 여부.
6. **relation 확장 착수 여부** 및 버전 운용(append vs v0.4 신규 export+DATA_URL).
