# MediStack v0.7 — 복합제(combo) tier 개방 정책 검토 문서 (검토 초안 v1 · 결정 전)

작성일: **2026-06-12** / 상태: **정책 검토만 — 코드/데이터/alias/validator 무변경. 복합제 편입은 PM 정책 결정 + 후속 설계 게이트 전까지 금지.** / 상위: `MediStack_v0.6_release_notes.md`, `MediStack_v0.6_handoff.md`, `MediStack_v0.6_alias_500_plan.md`

> v0.6 은 단일성분 트랙 천장 **alias 382** 에서 마감(`v0.6-beta`/`b168179`). 500 까지 잔여 118 은 현재 `복합제 금지` 불변규칙에 막힌 **복합제 deferred 풀에서만** 나온다. 이 문서는 **복합제 tier 를 열 것인가**를 의학적 완전성·안전·불변규칙 관점에서 실측 데이터로 검토하고, 정책 옵션과 권고를 제시한다. **이 문서는 결정 문서이며, 어떤 alias/코드/데이터도 바꾸지 않는다.**

---

## 1. 배경 / 검토 질문
- **현재**: alias 382 (단일성분 천장). relation 30 / DATA_URL / 앱 UI 불변.
- **500 잔여 118 의 유일 공급원** = deferred 복합제. 단일성분은 13 약물 완제 풀이 소진됨(v0.6 Phase 19~20).
- **검토 질문**: *복합제를 alias 검색 대상으로 편입할 것인가? 편입한다면 어디까지, 어떤 안전장치로?*
- **결정 전제**: MediStack 은 식약처 허가사항 기반 **약-영양소 참고 정보** 앱이며 진단·처방이 아니다. 안전 원칙 — *원문에 없으면 노출 금지 / 원문보다 강하거나 오도하면 금지.*

## 2. `복합제 금지` 규칙의 현재 정의와 근거
- v0.3~v0.6 전 과정에서 **복합제(combo)는 approved-ready·alias 진입 금지** 불변규칙이었다. 수집 단계에서 `ingr_name` 에 `/` 가 있으면 자동 `deferred` 강등.
- **근거(의학적)**: 우리 relation 데이터는 **단일성분 기준**(예: 메트포르민 × 비타민B12). 복합제는 성분이 2~3개인데, alias 는 제품→**단일 canonical 1개**로만 연결된다. 따라서 복합제를 1개 성분에 매핑하면 **제품 전체가 아니라 한 성분의 정보만** 노출된다 → 사용자가 제품 전체 약-영양소 정보로 오인할 위험.
- 이 규칙은 "안전 우선" 보수 정책이었고, 단일성분만으로 382 까지 충분했으므로 굳이 풀 필요가 없었다.

### 3-3. 🔑 의학적 완전성 — 결정적 구조
- **복합제 222 전부가 relation 보유 성분을 "정확히 1개"만 포함**(2개 이상 = 0건). 따라서:
  - ✅ **다중 canonical 매핑 충돌은 없다** — 어느 성분에 매핑할지 모호함이 없고, 항상 1개로 결정.
  - ⚠️ **그러나 본질적 부분정보다** — 제품은 성분 2~3개인데 그중 1개(relation 보유)의 약-영양소 정보만 보여줄 수 있다. 나머지 성분(글립틴·ARB·비타민D 등)은 우리 데이터에 없다.
- **부분정보 자체는 거짓이 아니다** (예: 가드메트정은 실제로 메트포르민을 함유하므로 메트포르민×B12 상호작용은 그 제품에 성립). 문제는 **사용자가 "이게 이 제품의 전체 약-영양소 정보"로 오인**하는 것. → **고지 없이 노출하면 안전 원칙("오도 금지") 위반 소지.**

### 3-4. 🔴 HCTZ 고유 위험 (가장 큰 그룹이자 가장 위험)
- HCTZ 복합제 112 는 전부 **HCTZ + ARB(사르탄)/CCB(암로디핀)** 고혈압 복합제.
- **칼륨 방향 상충**: HCTZ(치아지드 이뇨제)는 **칼륨 소실**, 파트너 ARB(로사르탄/발사르탄 등)는 **칼륨 보존(고칼륨혈증 위험)**. 복합제는 두 작용이 상쇄/복잡한데, 우리가 "HCTZ × 칼륨(소실 주의)" 정보만 보여주면 **반대 방향을 무시 → 의학적 오도.**
- 게다가 파트너 다수가 **로사르탄'칼륨'·피마사르탄'칼륨'** 염 형태 — 성분명에 칼륨이 들어가 혼선 가중.
- **칼륨 행은 이미 `potassium_safety_card=True` 특수 취급** — 단일 HCTZ 를 가정한 안전 문구가 복합제 맥락에선 부정확할 수 있다.
- **결론**: HCTZ 복합제는 부분정보 + 칼륨 오도 이중 위험 → **개방하더라도 HCTZ 는 제외 권고.**

## 4. 복합제 tier 가 건드리는 불변규칙 (단일성분과 다른 점)
복합제는 단일성분처럼 "alias 데이터만 추가"로 끝나지 않는다. 다음을 건드린다:
1. **`복합제 금지`** (직접) — PM 정책 완화 필요.
2. **`앱 UI 금지`** — 부분정보임을 알리는 **복합제 전용 고지**가 사실상 필수. 고지를 추가하려면 ① 앱 `render` 변경(복합제 배지/문구) + ② 데이터 또는 alias 에 `is_combination` 같은 append-only 플래그가 필요 → **앱 UI 불변규칙 완화 PM 승인 필요.**
3. **칼륨 안전(HCTZ 한정)** — `potassium_safety_card` 의 복합제 맥락 정확성. HCTZ 제외하면 회피 가능.
4. **안전 원칙(간접)** — 고지 없는 부분정보 노출은 "오도 금지" 위반 소지(§3-3).

> ⚠️ 핵심: **단일성분은 "X 관련 정보로 연결됩니다" 기존 안내로 충분했지만, 복합제는 고지가 추가로 필요**하고 그 고지는 앱 UI 변경을 수반한다. 즉 복합제 tier 는 **순수 데이터 작업이 아니다.**

## 6. 정책 옵션
- **B0 — 현상유지(382 마감 유지)**: 복합제 안 엶. 검색 시 복합제는 0건/기존 안내. v0.6-beta 그대로. **추가 위험 0.** 단 500 미달.
- **B1 — 안전 부분개방(권고 후보)**: **HCTZ 제외**, 메트포르민·알렌드론산·오메프라졸 복합제(110) + brand_core(14) 만. **복합제 전용 고지 필수**(부분정보 명시·앱 UI 고지 추가). 382 → ~506. 칼륨 오도 위험 회피.
- **B2 — 전면개방**: HCTZ 포함 복합제 222 전부. 604. **칼륨 오도 위험 큼 → 비권고.**
- **B3 — 고지 없는 alias-only 개방**: 앱 UI 안 건드리고 기존 안내만. **부분정보를 전체로 오인 → 안전 원칙 위반 소지 → 비권고.**
- **C — brand_core 14 단독**: 복합제 없이 brand stem 14 만. 382→396. 500 미달이나 위험 작음(별도 검토 문서 가치).

## 7. 권고
- **500 이 hard goal 이 아니라면 → B0(382 마감 유지).** 현재 커버리지로 검색 보조 목적은 충분하고, 복합제는 의학적 완전성·UI 변경·HCTZ 위험을 동반한다.
- **500 이 hard goal 이라면 → B1(HCTZ 제외 안전 부분개방).** 단 **전제 조건 2가지를 PM 이 명시 수용**해야 한다:
  1. **앱 UI 고지 추가 승인**(`앱 UI 금지` 완화) — 고지 없이는 B3 가 되어 비권고.
  2. **HCTZ 제외 동의** — 칼륨 오도 위험 회피.
- **어떤 경우에도 B2/B3 는 비권고**(B2=칼륨 오도, B3=오도 고지 누락).

## 9. B1 진행 시 후속 설계 게이트 (구현 아님 · 다음 문서에서)
> 아래는 *식별만* 하며, 이 문서에서 설계·구현하지 않는다. PM 이 B1 을 택하면 별도 설계 문서로.
- **combo sub-validator 설계**: `ingr_name` 에 `/` 허용 + **relation 보유 성분 정확히 1개** 검증(2개↑ FAIL) + canonical = 그 1개 + **HCTZ·에스오메프라졸 차단** + `is_combination=true` 플래그 정합.
- **복합제 고지 스키마/렌더**: append-only 플래그(`is_combination`, 선택적 `combo_partner_ingredients`) + 앱 `render` 복합제 배지 + 고지 1줄("이 제품은 복합제이며, 표시된 약-영양소 정보는 **OO 성분** 기준입니다. 다른 성분은 포함하지 않습니다.").
- **confirm 단계**: deferred 222 를 getItemDetail 로 distinct 성분 확정(미확정 후보 → 확정 수율 검증).
- **batch 게이트**: 단일성분과 동일한 생성↔반영 분리 + PM 명시 승인.
